# F-Droid submission draft

Noice-Fork is an independently maintained fork of Noice V1. The existing [Noice F-Droid entry](https://f-droid.org/packages/com.github.ashutoshgngwr.noice/) is not replaced. This fork has a separate application ID and bundles the soundbank for first-launch offline playback. The software is GPL-3.0-only; see the [individual sound credits and licenses](../audio-sources.json). The supported build has no Internet permission, tracking, or proprietary Google runtime dependencies. The inherited Google-connected flavor is disabled.

**Draft, not submitted.** Copy [`io.github.lrq3000.noicefork.yml`](io.github.lrq3000.noicefork.yml) to `metadata/` in a checkout of [fdroiddata](https://gitlab.com/fdroid/fdroiddata). Replace `REPLACE_WITH_PUBLISHED_COMMIT` with the full immutable revision containing the app and Fastlane metadata. Synchronize the version name, version code, and Fastlane changelog with that revision if it differs from the draft. Keep update checking manual until the project adopts a release-tag policy.

The draft selects the non-debug `free` build, not the GitHub Actions debug artifact and not a developer-signed binary. With JDK 17, Android SDK 35 and Build-Tools 35.0.0, run `./gradlew :app:assembleFreeRelease` from the project root. The unsigned APK is `app/build/outputs/apk/free/release/app-free-release-unsigned.apk`. Check its soundbank with `python3 scripts/verify_audio.py --apk app/build/outputs/apk/free/release/app-free-release-unsigned.apk`.

Before opening the fdroiddata merge request, add current fork screenshots if available and validate the draft with `fdroid lint io.github.lrq3000.noicefork`, `fdroid scanner io.github.lrq3000.noicefork`, and `fdroid build io.github.lrq3000.noicefork:56` from the fdroiddata checkout. Use the toolchain required by the published revision you selected. A local Gradle build alone does not confirm F-Droid scanner approval, inclusion, or reproducibility. Use the [official submission guide](https://f-droid.org/en/docs/Submitting_to_F-Droid_Quick_Start_Guide/) for the final handoff. Use the fork issue tracker for contact; no email is needed in the draft.
